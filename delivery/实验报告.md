# PCB 缺陷检测实验报告

> 算法：YOLOv8s　数据集：DeepPCB（6 类缺陷）　训练环境：CPU（Intel i5-13500H）

## 一、任务概述

对 PCB 板表面的 6 类缺陷进行检测与定位：

| 编号 | 类别 | 含义 |
|------|------|------|
| 0 | open | 开路 |
| 1 | short | 短路 |
| 2 | mousebite | 鼠咬 |
| 3 | spur | 毛刺 |
| 4 | copper | 杂铜 |
| 5 | pin-hole | 针孔 |

数据集规模：训练 1050 / 验证 300 / 测试 150 张（均为 640×640 灰度图）。

## 二、方法

### 1. 模型与训练策略

- 主干：**YOLOv8s**（11.1M 参数，预训练权重迁移学习）
- 优化器：AdamW，初始学习率 lr0=0.001，线性退火（cos_lr=False，lrf=0.01）
- 训练轮数：100 轮（分多次增量续训完成），batch=8，imgsz=640
- 数据增强：mosaic、scale=0.5、fliplr=0.5、hsv_v=0.3（灰度图仅保留亮度扰动）
- 硬件：纯 CPU 训练，单轮约 10.7 分钟，`cache=ram` 缓存加速

### 2. 评估方法

- **独立测试集评估**：150 张未参与训练/验证的图
- **TTA 测试增强**：`augment=True` 多尺度/翻转推理后聚合
- **置信度阈值扫描**：conf 从 0.05 扫到 0.50，寻找最优 F1

## 四、经验与教训

### 1. 学习率是震荡的元凶

`lr0=0.001` 对 AdamW 偏高，实测 mAP50-95 标准差高达 **0.129**，验证集 box loss 在 1.0~2.9 间反复跳。**修正：lr0 降到 0.0005**。

### 2. mosaic 对 PCB 检测反而有害

PCB 缺陷是规则几何图形，mosaic 四图拼接会切碎/错位走线，压低了 mAP50-95（定位精度），但不影响 mAP50（检出）。**修正：关闭 mosaic**。

### 3. 小数据集下堆轮数收益为零

100 轮 vs 10 轮仅提升 mAP50-95 **0.01**。1050 张图，20~30 轮即收敛，之后是过拟合（train box loss 降到 0.665 而验证集纹丝不动）。**修正：40 轮足矣**。

### 4. 断点续训的两个坑

- ultralytics 正常结束会把 `last.pt` 的 epoch 置为 -1 并清空 optimizer，直接 `resume` 会报"训练已完成"错误 → 需备份完整检查点（含 optimizer）
- 电脑在保存模型瞬间崩溃会写坏 `last.pt`（0 字节）→ 需保留 `best.pt` 作为兜底续训源

### 5. CPU 训练的实用技巧

- `cache=ram` 缓存数据进内存，避免每轮重复读盘
- 控制 `torch.set_num_threads` 避免线程争抢
- 纯 CPU 单轮 10.7 分钟，100 轮约 17 小时，需分次续训

## 五、结论

1. 最终模型 mAP50=0.9816、mAP50-95=0.6976，TTA 后 mAP50-95 达 **0.7279**
2. 检出能力（mAP50 0.98）接近饱和，瓶颈在细长小缺陷的**定位精度**
3. 后续改进方向：关闭 mosaic + 降低 lr0（见 `train_short.py`），预期 mAP50-95 提升至 0.72~0.75
